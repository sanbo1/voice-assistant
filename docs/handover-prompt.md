# 新しいセッションに渡すプロンプト

下の枠の中をそのままコピーして、新しいセッションの最初の発言として貼る。
（`docs/handover-2026-09-24.md` を読ませるだけでも足りるが、こちらは最初にやることを明示している。）

運用データの解析（2026-09-24 実施）は済んでいて、しきい値は据え置きになっている。
このプロンプトは、**その続きのセッション**用。

---

```
Raspberry Pi 5 で動く音声アシスタントの開発を引き継ぎます。
まず docs/handover-2026-09-24.md を読んで現状を把握してください。

前回は運用データを解析し、ウェイクワードの確認しきい値 0.55 と
聞き取りの確信度の足切り 0.52 は、データ上は変える根拠がないと結論しました。
ウェイクワードの反応が悪いという報告があり、私はスペースキーで代用しています。
改修は見送っていましたが、（ここに今回やりたいことを書く。例：
「反応の悪さがストレスになってきたので、取りこぼしの原因を調べたい」）

進め方について：

- 事実（確認済み）と推測（未確認）を区別して述べてください。
- 変更の前には原因を調べ、仮説を示してから直してください。
- 複数ファイルにまたがる変更は、着手前に方針を相談してください。
- Gemini への送信は無料枠（1 日 20 回）を消費します。送る前に必ず許可を取ってください。
- コミットと push は、私が指示したときだけ実行してください。
- 画面の表示を変えたときは、スクリーンショットで自分で確認してから報告してください。

まずは、引き継ぎメモを読んだうえで理解した現状と、提案があればそれを教えてください。
```

---

## 補足：引き継ぎメモを渡すだけでもよい

短く済ませたい場合は次の 1 行でも足りる。ただし「何をやりたいか」は伝わらないので、
上のプロンプトを使うほうが確実。

```
docs/handover-2026-09-24.md を読んで、現状を把握してください。
```

## 補足：引き継ぎメモの更新について

新しいセッションで作業が進んだら、`docs/handover-2026-09-24.md` を更新するか、
新しい日付のメモに置き換える。**古いメモは役目を終えたら削除する**（複数残すと、
どれが最新か分からなくなる）。
