# 構成と改良の選択肢

いまの構成と、各部分を改良する場合の選択肢・ランニングコスト・リスクをまとめたもの。
「次に何を改良するか」を考えるときの材料にする。

## この文書の扱い

- **値段・規約・無料枠は変わりやすい。** ここに書いた金額や条件は調査時点のもので、
  実際に検討する段になったら必ず公式の情報を確認し直す。確認日と出典を末尾に書いてある。
- **「未確認」と書いたものは推測**。実測していない。採用の判断は、できるだけ測ってから行う
  （例：2026-09-21 の音声認識モデルの大型化は、既存の録音で比較してから決めた）。
- 決定した内容は `docs/design.md` に、作業の履歴は `docs/verified-environments.md` に残す。
  この文書は「まだ決めていないこと」を置く場所。

## 2. 雑音の影響の測定（2026-09-22）

テレビと音楽（Echo Show）を鳴らした状態で録音し、認識結果と確信度を測った。
録音は Pi の `recordings/noise-test/` に残してある。質問はすべて
「ワンピースのルフィの身長は何センチですか」。

### 雑音だけ（誰も話さない）

| 条件 | 認識結果 | 平均確信度 |
|---|---|---|
| 静か | ん | 0.246 |
| **テレビだけ** | **ん他のそして秀吉** | **0.465** |
| 音楽だけ | ん | 0.255 |
| テレビ＋音楽 | （何も出ず） | — |

**文字になる雑音はテレビだけ。** テレビの音が人の話し声だからで、音楽は文字にならない。
この「ん他のそして秀吉」が 2 文字を超えるため AI に送られ、利用回数の枠を消費していた。

### 質問（距離と雑音の組み合わせ）

| 距離 | 条件 | SNR | 認識結果 | 確信度 |
|---|---|---|---|---|
| 目の前 | 静か | 23.6 dB | 正解 | 0.914 |
| 目の前 | テレビ | 20.0 dB | 正解 | 0.917 |
| 目の前 | 音楽 | 16.0 dB | 正解 | 0.920 |
| 約 5m | 静か | 8.8 dB | **正解** | 0.847 |
| 約 5m | テレビ | 7.8 dB | えー**いいねー１**身長は何センチですか | 0.792 |
| 約 5m | 音楽 | 6.7 dB | えー**今日はナンセンス**ですか | 0.576 |
| 約 5m | テレビ＋音楽 | 7.6 dB | **いいリリース日の**身長は何センチですか | 0.757 |
| 約 5m | テレビ・小声 | 8.9 dB | えーワンピース**がいいらしい**ですか | 0.722 |

**分かったこと**

- **距離そのものは問題ではない。** 5m でも静かなら完璧に認識される（SNR 8.8 dB）。
- **「離れて SNR が落ちた状態」＋「競合する音声」で崩れる。** 前半のフレーズが丸ごと別物になる。
- **距離 5m で SNR が 10〜13 dB 下がる。** 目の前なら 16 dB でも完璧なので、
  この 10 dB を取り戻せれば解決する見込みが高い。
- **確信度では「雑音」と「誤認識された質問」を区別できない。** 0.79 で全く違う言葉のことがある。
  確信度の足切りは利用回数の枠を守る対策であって、認識精度を上げるものではない。

### この測定を受けて実装したこと

- 聞き取りの確信度の平均が 0.52 未満なら AI に送らない（`.env` の `VOSK_MIN_CONFIDENCE`）。
  雑音（0.465）だけを止め、質問（0.576〜0.920）はすべて通ることを録音 12 件で確認した。
  余裕は狭い（0.465 と 0.576 の間）ため、呼びかけが無視されるようなら下げる。
- 確信度を会話ログに毎回記録する（実運用のデータでしきい値を調整するため）。

| 改良案 | ランニングコスト | 良くなる点 | リスク・課題 |

| 改良案 | ランニングコスト | 良くなる点 | リスク・課題 |

### AI（応答生成）

| 改良案 | ランニングコスト | 良くなる点 | リスク・課題 |
|---|---|---|---|
| 現行（無料枠） | 無料（アカウント必要。1 日 20 回／モデル） | 費用ゼロ | 枠を超えると予備モデルへ。**入力が Google の製品改善に使われる** |
| 有料プランへ移行 | 従量課金。**いまの使い方なら月 $1〜2 程度**（※2） | 枠の制限から解放。**入力が製品改善に使われない** | 費用が発生。2027-01-01 に値上げ予定 |
| ローカル LLM（llama.cpp など） | 無料（電気代のみ） | 枠・オフライン・プライバシーがすべて解決 | **Pi 5 の CPU では応答が実用にならない可能性が高い**（いまでも AI に 3.6〜11.8 秒かかっている） |
| 優先モデルを枠の大きいものに変える | 無料 | 予備モデルへの切り替え頻度が下がる | モデルごとの枠は AI Studio で都度確認が必要。応答品質が変わる可能性 |
| 検索によるグラウンディング（天気・ニュースに答える） | **課金が必要**（※3） | 天気やニュースに実際に答えられるようになる | **利用規約で検索候補の表示が求められる**ため、画面が必要。応答時間への影響は未計測 |
| 画像の生成 | **課金が必要**（無料枠なし） | 画像を見せられる | 1 枚 $0.034〜0.24。画面が必要。意図の判定（「絵を描いて」と「教えて」）が要る |
| 動画の生成（Veo 3.1） | **課金が必要**（無料枠なし） | 動画を見せられる | **$0.05〜0.60／秒**。5 秒で 40〜450 円と桁が違う。生成に数分 |

※3 2026-09-23 に実機で確認：`gemini-3.6-flash` に `"tools": [{"google_search": {}}]` を付けて送ると
**HTTP 429（枠の超過）**で拒否された。同じタイミングで検索なしのリクエストは成功しているため、
1 日 20 回の生成の枠ではなく、検索そのものが無料枠の対象外と判断した。
エラーの詳細に上限の種類は返らず、メッセージは課金の有効化を促す内容だった。

なお**公式ドキュメントの書き方 `{"type": "google_search"}` は HTTP 400 で拒否された**（従来の
`{"google_search": {}}` が受け付けられた）。採用するときは書き方も実機で確認すること。

※2 概算の根拠：1 日 30 回、1 回あたり入力 1,000 トークン・出力 200 トークンと仮定。
`gemini-3.5-flash-lite` 相当（入力 $0.30／出力 $2.50 per 1M トークン）で月約 $0.7、
`gemini-3.8-flash` 相当（$0.75／$3.75）で月約 $1.4。
**使用中の `gemini-3.6-flash` の単価は料金表に見当たらず、近いモデルからの推定**。

## 4. 優先度の考え方（2026-09-22 更新）

### 前提となる方針：人が自然と良い条件を選べるようにする

このシステムは開発者だけでなく**家族も使う**。中の仕組みを知らない人でも困らないことが重要。
そのため「技術で全条件を完璧にする」より、**人が自然と良い条件を選べる形に誘導する**方針を取る。

- 静かなときは、いままでどおり離れた場所から話しかけられる（利便性を残す）
- **うるさいときは認識率が落ちる**ことには人が慣れてもらう
- **うるさいときはボタンを押して近くから話す**という逃げ道を用意する

この方針に照らすと、「ボタン＋近接マイク」は**分かりやすく確実な逃げ道**になるため優先度が高い。

### 優先順位

1. **ボタン＋近接マイク**（部品は手元にある。上の方針に最も合う。
   誤反応・録音範囲・SNR の 3 つに同時に効く）
2. **マイクアレイ**（どこからでも話しかける使い方を保ったまま SNR を改善できる唯一の手段。
   ただし効果は未確認）
3. SD カードの交換（起動時間。効果は実測済みで費用も小さい）
4. 音声合成・音声認識の差し替え（効果は期待できるが、応答速度とのトレードオフ）

### 効果が見込めないと分かったもの

- **マイクを 1 か所に近づける** … 話す場所が定まらないため成立しない（2026-09-22）
- **ソフトの雑音抑制**（RNNoise など）… 妨害しているのが人の話し声（テレビ）のため、
  音声でない雑音を消す仕組みは効かない
